# 음성 요약 웹서비스 · 자료 기반 재구현

2026년 1학기 4인 팀 프로젝트의 결과 보고서를 바탕으로 2026-10-28에 새로 구현했습니다. 당시 원본 코드 복구본이 아닙니다. 이수빈의 당시 역할은 팀원으로 백엔드·AI 연동·데이터 처리 참여이며, 이번 재구현에는 AI 도구를 활용했습니다.

## 실행

Python 3.12에서 기본 모드를 검증했습니다.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8001
```

http://127.0.0.1:8001 에서 회원가입 후 사용합니다. 기본 설정에서는 텍스트 입력으로 작업 등록·조회·결과 저장 흐름을 확인할 수 있습니다. API 키가 없으면 앞부분 문장 추출을 사용하며 **AI 요약이 아님**을 표시합니다.

### 실제 음성 인식과 Gemini 연결

1. FFmpeg를 설치하고 PATH에 등록합니다.
2. `pip install -r requirements-whisper.txt`를 실행합니다.
3. `ENABLE_WHISPER=1`, 필요 시 `WHISPER_MODEL=base`를 설정합니다.
4. `GEMINI_API_KEY`를 서버 환경변수로 설정합니다.
5. 서버를 시작합니다. Whisper 모델은 시작 시 한 번 로드합니다.

Whisper 모델은 최초 다운로드가 필요합니다. 2026-10-28에 base 모델과 FFmpeg로 OpenAI Whisper 저장소의 공개 영어 음성 tests/jfk.flac을 실제 전사했습니다. 업로드 → 전사 → 결과 저장 → 임시 음성 삭제를 확인했습니다. verification.json에 결과를 기록했습니다. 단일 영어 샘플 확인이며 한국어 정확도·긴 파일 성능 평가는 아닙니다. Gemini 실제 API 응답은 검증하지 않았습니다.

## 주요 구조

업로드 → task_id 반환 → BackgroundTasks에서 음성 인식·요약 → 5초 간격 상태 조회. SQLite에 사용자별 작업을 저장하고 본인 기록만 조회·삭제할 수 있습니다. 음성 파일은 성공·실패 모두 처리 후 삭제합니다. 변환 원문과 요약은 기록 삭제 전까지 남으므로 '모든 데이터 무보관'으로 설명하지 않습니다.

## 원자료와 차이

- 보고서의 사용자별 API 키 저장 대신 서버 환경변수로 키를 관리합니다.
- 기본 업로드 한도는 50MB입니다. `MAX_UPLOAD_MB`로 변경할 수 있습니다. 보고서의 500MB 처리 성능을 검증했다고 주장하지 않습니다.
- 시작 시 중단된 작업을 실패로 표시하고 임시 음성 파일을 정리합니다.
- 비밀번호 PBKDF2, HTTPOnly 세션 쿠키, CSRF 토큰, 작업 소유자 검사를 추가했습니다.
- UI와 텍스트 입력·대체 요약은 포트폴리오 검증을 위해 새로 작성했습니다.

## 테스트

```bash
pip install pytest==8.4.2 httpx==0.25.2
pytest -q
```

2026-10-28: 5개 자동 테스트 통과. 텍스트 작업 생성·조회·삭제, CSRF·사용자 분리, 음성 처리 성공/실패 시 파일 삭제, 용량 제한, 재시작 중단 작업 정리, 비밀번호 비평문 저장을 확인했습니다. 음성 처리 테스트는 **전사 대역 함수**를 사용합니다. 이 자동 테스트 자체는 실제 Whisper 검증이 아닙니다. 실제 음성 처리는 verification.json의 별도 확인 기록을 참고하세요. 예시 키 무호출과 API 시간 초과 시 대체 요약도 테스트했습니다.

학습용 단일 프로세스입니다. 영속 작업 큐·분산 처리·요청 속도 제한·운영 모니터링은 구현하지 않았습니다. 여러 worker를 사용하지 마세요. 외부 공개 운영 시 HTTPS와 `COOKIE_SECURE=1` 및 추가 보안 검토가 필요합니다.

## 환경변수 예시

`.env.example`은 설정 항목 안내이며 자동으로 읽지 않습니다. 실행 전에 터미널 환경변수로 설정하세요. `GEMINI_API_KEY`가 비어 있거나 `your_api_key_here`이면 실제 호출 없이 대체 동작을 사용합니다. 실제 키와 사용자 DB는 저장소에 포함하지 않습니다.
